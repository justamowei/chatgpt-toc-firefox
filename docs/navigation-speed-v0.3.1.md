# v0.3.1 收集與離屏定位修正

2026-10-04（Asia/Taipei）。使用者確認已看過的提問都可保存，但較早收集只新增1–2則便顯示「已達載入上限；可稍後重試」，離屏定位也慢慢逐步捲動。

## 原邏輯與原因

v0.3.0 的收集和尋找共用最多20批／60秒，每步0.7 viewport且固定等待約1.8秒。一次最多約14 viewport；大型回答足以耗盡這項預算。回報提示可確認是預算觸顶，不證明歷史已完整，也不能在沒有當時elapsed/batches數據時指認該次一定是步數而非時間。進展原本只看新ID／scrollTop淨變化，網站的閱讀錨定與高度重估也可能影響判讀。

## 候選實作

- 收集與seek分開：最多240／60步，總期限仍60秒。自適應掛載settle取代每步固定1.8秒；空／載入窗口必須等待可驗證的可見訊息，不能因為舊DOM剛卸載就繼續。每步0.85 viewport留重疊。
- 收集可跨過目前明確掛載的assistant正文內部，只停在邊緣並保留重疊；若有其他已辨識turn相交就拒絕跨過，不跳未知提問。
- 已觀察訊息另保存純數字位置／高度線索，沒有保存卸載DOM。seek先嘗試位置線索，位置失準時用實際掛載user座標／可信順序收縮搜尋範圍。保留尾端兩輪不代表閱讀錨點；畫面外很遠的提問不當作scrollTop所在位置。
- 高度或實際user座標改變，作廢舊界限及嘗試紀錄。位置只是嘗試線索，成功仍需重新掛載精確ID／角色／正文、同context／epoch、connected與viewport；scrollIntoView後還要等待可能的非同步替換。
- 明示時間上限、步數上限及本次新增提問數；停止、手動介入、換頁仍取消晚到任務，已有快取保留。

## 驗證狀態

核心22項與typecheck通過。GPT-6.1 Sol high唯讀審查指出的deadline分類、錯用scrollTop界限、舊幾何嘗試紀錄、空窗口過早步進、跨回答其他turn檢查均已修正。隔離Firefox速度／快取回歸進行中，尚未宣稱PASS。第一次速度測試已收齊40，但頁面realm覆寫scrollTo無法記錄extension realm方法，已改成量測真實scroll事件；不把該次失敗當PASS。
